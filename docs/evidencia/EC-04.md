# Evidencia EC-04 / RNF-004 / PR-12: prueba de carga de la comparación

**Fecha:** 17 de noviembre de 2026 · **Issue:** #35 · **Corrida:** [Actions 44078248800](https://github.com/JuanJo0775/Sistema_valora_B/actions/runs/44078248800) · **Datos:** [`ec-04-2026-11-17.json`](ec-04-2026-11-17.json) · **Script:** `test/load/comparison.k6.js` (workflow `load.yml`)

## Escenario

- **Entorno:** el despliegue de `main` (ADR-012): API en **Render plan gratuito** (Docker), base en **Neon plan gratuito**. La carga sale de un runner de GitHub Actions.
- **Calentamiento:** 5 usuarios durante 90 s para despertar Render y Neon. No cuenta en el resultado (umbrales filtrados por escenario).
- **Carga:** **500 usuarios virtuales**, rampa de 1 minuto, **10 minutos sostenidos** y 15 s de bajada.
- Cada usuario consulta `GET /v1/products/{id}/comparison?municipality=…` (Armenia en 4 de cada 5, otro municipio en 1 de cada 5; sin ubicación) y piensa de 1 a 3 s entre consultas.
- **Meta:** p95 ≤ 2 s y tasa de error < 1 %.

**EC-04 no se cumple en el entorno desplegado actual.** Se registra tal como salió.

## Causa probable

- **La instancia gratuita de Render no da para 500 usuarios.** Tiene una fracción de CPU y poca memoria; con unas 114 consultas por segundo se satura. Las respuestas en error salen rápido (p50 de 199 ms con 71 % de errores), lo que encaja con el proxy de Render devolviendo 5xx cuando la instancia no alcanza a responder, más que con consultas lentas a la base.
- **La comparación por municipio no aprovecha caché.** Cada consulta vuelve a la API y a la base, aunque 500 personas pregunten por los mismos productos.
- La prueba no separa todavía los códigos 502, 503 y 504, ni mide la base por separado: no se puede afirmar si Neon también se saturó.
- Después de la carga la API se recuperó sola (`/v1/health` 200 en 0,4 s).

## Plan

1. **Medir la capacidad real del plan gratuito**: repetir con 25, 50, 100 y 200 usuarios para encontrar el punto de quiebre, y separar los 5xx por código. Así queda claro hasta dónde llega hoy.
2. **Caché en la comparación por municipio** (EC-04 ya la pide para lecturas públicas): `Cache-Control` corto y `ETag`, como el directorio y la canasta. La comparación con ubicación sigue sin caché (EC-08).
3. **Revisar el pool de conexiones** a Neon y los índices de `price_current` bajo carga.
4. **Volver a medir con una instancia con más recursos** (por ejemplo, el plan de pago más pequeño de Render) solo durante la prueba, para separar el límite del plan del límite del diseño. Es una decisión de costo del equipo (ADR-012).

La issue #35 queda abierta hasta cumplir la meta o registrar la decisión del equipo.
